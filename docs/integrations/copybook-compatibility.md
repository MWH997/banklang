# Copybook Compatibility

## Purpose

Copybooks are adoption-critical. Existing banks use copybooks as shared data-layout contracts.

## Source of truth

Use IBM Enterprise COBOL COPY statement documentation and IBM copybook/data-layout documentation.

## BankLang requirements

BankLang must support:

- BankTS record to copybook generation
- copybook parser subset
- copybook layout inspector
- copybook diff
- field offset reports
- packed decimal reports
- COPY dependency graph

## COPY statement implications

The COBOL COPY statement brings prewritten source text into a compilation unit at compile time. This means BankLang must treat copybooks as build-time dependencies, not runtime schemas.

## Initial supported subset

- `01` records
- nested groups
- `PIC X(n)`
- `PIC 9(n)`
- signed numeric fields
- `COMP-3`
- fixed `OCCURS`
- `88` condition names where generated by BankLang

## Roadmap subset

- `REDEFINES`
- `OCCURS DEPENDING ON`
- multiple 01-level record variants
- COPY REPLACING
- dialect-specific copybook patterns

## Required evidence

- layout report
- byte length
- field offsets
- PIC/usage
- unsupported construct diagnostics
- before/after diff
