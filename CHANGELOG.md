# Changelog

## Unreleased

### Added

- Added `returnCode = <n>;`, the step's condition code. It lands in COBOL's `RETURN-CODE` and reaches the job as the value the next step's `COND=` tests; without it every step reported success, and a job that found no records looked exactly like one that processed a million. The value must be a whole number in 0–4095, which is what `RETURN-CODE` holds. `SORT`, `MERGE`, and checkpoint/restart are not included and the reference says so.
- Added the unit of work and positioned update to the Db2 profile. `INSERT`, `UPDATE`, and `DELETE` already worked, because a `sql` declaration carries whatever statement was written; what was missing was the ability to end a unit of work and to update the row a cursor is sitting on. `commit;` and `rollback;` lower to `EXEC SQL COMMIT` and `EXEC SQL ROLLBACK`. Neither is allowed inside a `cics transaction`, which finally gives `BANK-SQL-004` — reserved from the start as "transaction commit ambiguity" — the meaning it was waiting for: CICS owns the syncpoint there and commits Db2's work along with everything else, so an `EXEC SQL COMMIT` is not merely redundant but rejected by Db2 at run time. `WHERE CURRENT OF <cursor>` now rewrites the cursor to its COBOL name, without which a positioned update refers to a cursor Db2 has never heard of.
- Added the rest of VSAM: `update` mode, `rewrite`, `delete`, and the `start` / `readNext` browse. With only `open`, `read`, `write`, and `close`, and files that were either input or output, a master file update — the archetypal batch program — could not be written at all. `update` opens I-O, so the same `OPEN` serves the read that finds a record and the rewrite that puts it back. An indexed file is now `ACCESS MODE IS DYNAMIC` rather than `RANDOM`, because it is both read by key and browsed and `RANDOM` allows only the first. `START` uses `KEY IS NOT LESS THAN`, which begins at the first record at or after the key — an exact match would make a browse from a partial key impossible. A `write` or `rewrite` to an indexed file now captures `INVALID KEY`, because a duplicate key is the failure a KSDS write actually has and it is otherwise silent. `BANK-FILE-005` reports an operation the declaration cannot support.
- Added string handling: `trim`, `upper`, `lower`, `substring`, `concat`, and `now`. Without these a program could not assemble a narrative, parse a composite key, or mask a card number — so the `sensitive` declassification rule, which treats a function call as the boundary, rested on a masking function that could only return a constant. `concat("************", substring(pan, 16, 4))` is now a real mask. Every result has a length the compiler can name, because a COBOL field has a fixed one: `substring` takes literal bounds and rejects a slice running past the end, and `concat` sums its arguments. A computed string pads into a wider field exactly as a written literal does, and will not truncate into a narrower one. `concat` and `now` lower to a `STRING` statement rather than appearing inline, clearing the target first because `STRING` leaves whatever was past the end alone. `now()` assembles a Db2 timestamp from `CURRENT-DATE`, whose hundredths are all the clock offers, so the last four digits of the microseconds are zeros rather than invented. `INSPECT`, `UNSTRING`, and `SEARCH` are not included and the reference says so.
- Added `copybookMode`, a project setting choosing whether record layouts are written into the generated program or copied into it. The compiler emitted `.cpy` files and then inlined every record anyway, so nothing ever copied them — in a real shop the copybook is the contract between programs, and a program that does not `COPY` it can drift from it silently, which is the defect the copybook exists to prevent. `inline` stays the default, because a self-contained artifact is what the playground shows and what a reviewer reads on its own. `copy` emits `COPY <NAME>.`, adds a `SYSLIB` to the generated job's compile step, and puts the copybook directory on the local validation compiler's search path, so the mode that ships is the mode that is checked.
- Added `binary<n>` and `zoned<p, s>` alongside packed `decimal<p, s>`. Every number the compiler emitted was `COMP-3`, which meant it could not represent — and therefore could not read — most fields in an existing estate's copybooks: the halfword counters, the fullword sequence numbers, and the zoned decimal that much legacy input arrives as. A binary field is held in the halfword, fullword, or doubleword that fits its digit count, the way IBM Enterprise COBOL allocates `COMP`, and more than eighteen digits is `BANK-TYPE-002`. Zoned decimal is one byte per digit with a separate sign, so the field reads as plain text. Usage is representation and not meaning: it takes no part in type compatibility, only in the picture and the byte count, and the layout report now names it.
- Added `edited<T, "style">`, the numeric-edited items a mainframe program uses to put a number in front of a person. An amount held as `COMP-3` cannot be printed, so a statement whose amounts have no rendering is not a statement. Six styles cover what banking actually uses — zero suppression, thousands grouping, a trailing minus, `CR` for a credit, asterisk cheque protection, and a slashed date — and the picture is generated from the value's own precision and scale rather than written out, so nobody counts `Z`s. Assignment into the field is the formatting step, which is what a COBOL `MOVE` into a numeric-edited item does; the compiler emits `MOVE` rather than `COMPUTE`, because COBOL rejects the latter. An edited field is a rendering and not a number: it cannot be read back as a value, compared, or computed with, which stops a report column becoming arithmetic input and losing the digits the editing removed. An unknown style is `BANK-TYPE-023` rather than a picture passed through unchecked.
- Added `date`, `time`, and `timestamp`, with the calendar arithmetic that goes with them: `today()`, `addDays(when, days)`, and `daysBetween(from, to)`. A date is stored as `PIC 9(8)` holding `YYYYMMDD`, the mainframe convention, chosen because in that layout ordinary numeric comparison is also chronological comparison; a timestamp is `PIC X(26)`, Db2's own host variable format. Dates are nominally typed, so one cannot be compared with an amount or with a plain integer that happens to have eight digits. The arithmetic lowers to the COBOL intrinsics that know the calendar — `CURRENT-DATE`, `INTEGER-OF-DATE`, `DATE-OF-INTEGER` — rather than to `+` on the stored digits, because thirty days after the 31st of January is the 2nd of March. The language reference had listed `date`, `time`, `timestamp`, `int<n>`, and `uint<n>` as supported since the first release; three of them now are, and the two integer types have been removed from the list rather than left as a claim the compiler rejects.
- Added `sensitive` as a record field modifier, and the checks that make it mean something. A value marked sensitive may not reach an audit event or a ledger posting (`BANK-AUD-002`) — both are durable records that outlive the transaction and are read by people with no business seeing a card number — and may not be assigned to a field that is not itself marked (`BANK-SEC-001`), because a field's marking is part of its copybook and copying restricted data into an unmarked field would reclassify it silently. The check follows a value through locals. It deliberately does not follow one across a function call: that is the declassification point, made explicit rather than hidden, because following taint across a call needs per-function summaries and a language with no closures can express masking no other way. The copybook layout report now marks which fields carry restricted data, so an auditor reading the evidence does not have to read the source. `BANK-AUD-002` was reserved from the start; this is what it turned out to mean.
- Added Db2 cursors: `cursor <name>(...): <Record> { SELECT ... }` declares one, and `for each <row> in <cursor>(...) limit <n> { ... }` reads it. The `OPEN` and the `CLOSE` are generated around the body rather than written, so a cursor cannot be left open — a cursor still holding Db2 locks at the end of a batch window is a defect the language can make unwritable rather than diagnose. The bound is mandatory for the reason a `while` bound is (`BANK-TXN-004`), and the loop leaves on any non-zero `SQLCODE` rather than only on 100, because an error treated as end-of-data processes a partial result set as though it were the whole one. `DECLARE CURSOR` may not carry an `INTO`, so the author writes it on the SELECT where the query reads best and the compiler moves it to the `FETCH`; a cursor with no result record or no `INTO` is `BANK-SQL-006`. Confusing a cursor with a single-row statement is `BANK-SQL-005`.
- Added `examples/branch-accrual-cursor`, a batch Db2 program that reads a branch through a cursor and accrues interest, executed against the reference runtime in four scripted shapes: rows then end-of-data, no rows at all, rows that never run out, and an error mid-stream.
- Added record inheritance with `extends`. Base fields are laid out first, so a derived record's leading storage is the base record's storage byte for byte and an existing copybook for the base still reads a derived record. A derived record may be passed where the base is expected: a function's record parameter is a `LINKAGE` cell the caller points at the argument with `SET ADDRESS OF`, so the callee reads the derived record's own storage at the offsets `extends` guarantees. An argument with no address the caller can take — a subscripted element — is still `BANK-TYPE-021`. Cycles are `BANK-TYPE-016` and redeclared inherited fields are `BANK-TYPE-017`.
- Added generics on records and functions, monomorphised at compile time. COBOL has no boxing and no runtime polymorphism, so every instantiation expands into a concrete record or paragraph. Type arguments are normalised through the resolver before they name an instantiation, so `Slot<Money>` and `Slot<currency<"BDT", 18, 2>>` share one record. Generic functions infer their type arguments from the argument types, because `f<T>(x)` cannot be told apart from two comparisons without unbounded lookahead. New diagnostics: `BANK-TYPE-014`, `BANK-TYPE-015`, `BANK-TYPE-018`, `BANK-TYPE-019`, `BANK-TYPE-020`.
- Instantiated functions that lower to identical COBOL now share one paragraph. `larger<currency<"BDT", 18, 2>>` and `larger<currency<"USD", 18, 2>>` both emit `PIC S9(16)V99 COMP-3`, so emitting both was the same paragraph and the same storage twice. Sharing runs to a fixpoint, because two instantiations of a caller differ only in the callee they name until those callees merge, and the surviving name is the alphabetically first of the group so it does not depend on instantiation order. This changes what is emitted and not what is accepted: currency stays nominally typed, and a function the author named is never merged.
- The reference Db2 and CICS runtimes now report outcomes a test scripts, instead of always reporting success. `DSNHLI` receives the statement descriptor Db2 numbers its statements with, and `DFHEI1` receives the command name and returns its response in `EIBRESP` the way CICS does, with the translator emitting the `MOVE EIBRESP TO ...` that a `RESP` option asks for. A test seeding `SQLCODE 100` or `PGMIDERR` now executes the branch a generated program guards with `sqlcode == 0` or a `resp` test, rather than reading it out of the emitted COBOL. Every such value is still written down by the test: it says what the generated program does, not what Db2 or CICS would return.
- Added a failure model: `raise "CODE"` abandons the body, and an `on failure` block on a transaction handles it. It lowers to `BANK-FAILURE-CODE` plus a `GO TO` the body's exit paragraph, with the wrapper performing the body `THRU` that paragraph — a `GO TO` out of a plain `PERFORM` range leaves the flow of control undefined. Failures cross `PERFORM` boundaries because the caller tests the code, and cross `CALL` boundaries because the field is `EXTERNAL`. `if <bad> { raise "..."; }` is a guard clause needing no `else`. Handlers may not raise (`BANK-TXN-009`), and codes must fit `PIC X(32)` (`BANK-TXN-008`).
- A transaction that posted to the ledger now calls `BANKLEDG` with `ROLLBK` on its failure path, before the handler runs. BankLang does not own the ledger, so it delegates rather than generating compensating postings of its own.
- Added `entry transaction`. COBOL enters a program at the first statement of the `PROCEDURE DIVISION`, which previously meant whichever declaration happened to be emitted first — usually a helper function. The backend now emits a `BANK-MAIN` paragraph that performs the designated transaction, defaulting to the first declared one. Two entry points is `BANK-TXN-010`.
- Added a reference runtime in `runtime/`: `BANKLEDG`, `BANKAUDT`, `DSNHLI`, and `DFHEI1`. These satisfy the interfaces generated code calls out to, so a generated program can be executed rather than only compiled. They are small COBOL programs in this repository and imply no IBM behaviour; `runtime/README.md` states exactly what running against them does and does not establish.
- Added `tests/conformance.test.ts` and `tools/conformance.ts`, which compile a BankTS program, link it against the reference runtime, run it against seeded packed-decimal input, and assert on the ledger journal, the closing balances, the audit log, and the output records. Record layouts come from the compiler's own layout report rather than hand-counted offsets.
- Added `examples/withdrawal-with-recovery`, the first example that is executed rather than only compiled.
- Ledger postings now accept `currency` amounts. Previously only plain `decimal` was allowed, which made every currency-typed balance unpostable and defeated the purpose of having currency types.

### Fixed

- The generated JCL described a build that could not succeed. A program with embedded SQL got the same three-line skeleton as a plain one: no `DSNHPC` precompile, no bind, no Db2 load library, and a CICS program got no translator step. A batch program's declared files had no DD statements, so the job could not have run even after compiling. The job now carries the steps the program actually needs — translate, precompile, compile, link-edit, bind — in the order z/OS needs them, with a DD for each declared file named after the DD the generated `SELECT` assigns to, and the load module named consistently across the link-edit, the bind, and the run step. A CICS program gets no run step and says why: it is started by a transaction identifier in a region, not by `EXEC PGM`.
- The playground highlighter and the VS Code grammar had both fallen behind the lexer: `cursor` and `sensitive` were accepted by the compiler while both editors rendered them as ordinary identifiers, and the grammar had never learned `currency` or `nullable`. The parser now exports its keyword list and `tests/editor-surfaces.test.ts` compares all three, in both directions — a word the lexer does not reserve must not be highlighted as though it were.
- Six of the ten examples had no title or description in the playground picker, so they showed a directory name and an empty blurb, sorted last. The ones that needed explaining most — cursors, failures, CICS — were among them. Every example is now described, and a test fails if a new one is added without a description.
- The banking checks never looked inside a loop. `flattenStatements` descended only into `if`, so a transaction whose only posting was inside a `while`, a `for each`, or a `switch` branch had, as far as the double-entry check could see, no postings at all — and balanced trivially. Money moving inside a loop is money moving, so every nested block is now flattened.
- Passing a record to a function generated a `MOVE` into a `-Pn` field that was never declared, so the program did not compile. Record parameters are now `LINKAGE` cells the caller points at the argument, so no move is needed; an argument with no address the caller can take is `BANK-TYPE-021` rather than silently reading a different group.
- Every non-failing function paragraph ended with `GOBACK.`, so performing one ended the whole program at the first function call. It compiled perfectly and exited 0, having posted nothing — which is why it survived until a generated program was actually executed. A function paragraph now ends with `CONTINUE.`, because `PERFORM` returns at the end of a paragraph on its own.
- Two routines that each declared a local with the same name emitted two `01` items with that name, and different `PICTURE`s when the two locals had different types, so every reference to it was ambiguous. A local only one routine declares keeps its name; one that more than one routine declares is qualified with its owner, the way parameters and results already are. Qualifying only on collision keeps names inside the 30-character limit that a transaction name plus a local name can exceed.
- A `let` declared inside a `while`, a `for each`, or a `switch` branch was given no storage at all, so the generated program referenced a name it never declared. Locals are now collected from every nested block, since COBOL has no block scope and all of them need an `01` item.
- The reserved-word list covered 221 words and missed `PRESENT`, `VALUE`, `DOUBLE`, and 300 others, so a field or function with one of those names emitted COBOL the compiler rejected. It is now the union of the IBM Enterprise COBOL reserved words and every word GnuCOBOL reserves unconditionally.
- An out-of-range computed subscript was clamped to the array bound, which ran the statement against a substituted element — the exact defect the check exists to prevent. It now raises `BANK-BOUNDS-VIOLATION` where a handler can see it. `BANK-BOUNDS-STATUS` still records `"23"` for an operator reading a dump.
- A ledger amount wider than `PIC S9(16)V99` was truncated silently by the generated `MOVE`. It is now `BANK-LED-004`, closing a gap ADR-0003 had recorded but not enforced.

- Added the comparison operators `<`, `<=`, `>=`, `==`, and `!=`. Previously `>` was the only one, which made most banking conditions impossible to express. Ordering stays decimal-only; equality also works on strings and bools.
- Added the logical operators `&&`, `||`, and `!`, with a full precedence chain: `||`, `&&`, comparison, additive, multiplicative, unary.
- Added multiplication, which adds the operand scales, and `BANK-DEC-004` when the result needs more digits than the declared precision allows.
- Added `round(expr, "MODE")` and `divide(a, b, "MODE")` covering seven COBOL rounding modes. A bare `/` is rejected as `BANK-DEC-003`, and a narrowing assignment without rounding is `BANK-DEC-002`. Rounding lowers to `COMPUTE ... ROUNDED MODE IS`, taking the scale of the assignment target exactly as COBOL does.
- Added function calls, including calls to functions declared later in the file. Calls lower to argument moves plus a `PERFORM`, with nested calls ordered so inner results are ready first.
- Added `while <condition> limit <n>` loops. The limit is mandatory (`BANK-TXN-004`) and becomes a guard counter in the generated COBOL, so a loop whose condition never goes false still terminates.
- Added assignment to locals and record fields.
- Added the file operations `open`, `read into`, `write from`, and `close`, with `BANK-FILE-001` for direction mismatches and `BANK-FILE-002` for record layout mismatches. A `read` sets the status field at end of file, and status fields are readable symbols so a batch loop can test them.
- Added `if` / `else` inside transaction bodies, branching on effects rather than on a returned value.

- Fixed CICS response variables being referenced but never declared in working storage, so a generated CICS program named data items that did not exist. Found by compiling the translated output for the first time.
- Fixed COBOL reserved words being emitted as record and paragraph names; the mangling previously applied only to field names.
- Fixed paragraph names colliding with data names, which COBOL treats as one namespace. A transaction named `total` alongside a field named `total` now emits `TOTAL-PARA`, and only when it would actually collide.
- Fixed COBOL file names colliding with record type names, which happens whenever a file and its record share a name. File names are now suffixed `-FILE`.
- Fixed decimal literal precision being computed below its own scale, so `0.00` was typed `decimal<1, 2>` and rejected everywhere.
- Fixed string literals being compared by exact length rather than fitting any field long enough to hold them.
- Fixed currency rejecting multiplication by a plain decimal. Scaling money by a dimensionless rate is a normal banking operation and keeps the currency; adding across types is still `BANK-DEC-005`.
- Fixed `round()` rejecting currency operands.
- Fixed nested group items reusing COBOL level 05 instead of stepping to 10, which `OCCURS` made fatal.
- Fixed source map field attribution, which assumed one emitted line per record field. Enums, nullables, and arrays emit several, and `BANK-GEN-006` caught the drift. Field start lines are now recorded as they are emitted, closing the gap noted when that check was added.
- Fixed FD records being emitted as opaque buffers. They now carry the real field structure with qualified references, so per-field mapping works.
- Fixed string literals being typed by their exact written length, so a literal now fits any string field long enough to hold it. COBOL `MOVE` pads with spaces, so this is not a silent truncation.
- Fixed function parameters never being declared in working storage. A parameter reference only resolved when it happened to share a name with a record field, so `validateAmount(amount)` read the record's `AMOUNT` rather than its argument, and calling a function was impossible. Parameters now get their own storage; record parameters resolve to the record group item.
- Fixed decimal literals being typed by their written width, which forced `0000000000000025.00` to assign to a `decimal<18, 2>`. A literal now widens to any decimal with the same scale and enough precision. The scale must still match exactly, because changing scale is a rounding decision.
- Fixed generated COBOL for functions whose body is an `if` / `else`. A `GOBACK.` was emitted inside each branch, and the period terminated the COBOL sentence, leaving the following `ELSE` and `END-IF` dangling. GnuCOBOL rejected the batch-interest-accrual output with `syntax error, unexpected ELSE`. Return statements now assign only the result field and each paragraph ends with a single `GOBACK.`. The batch-interest-accrual golden fixture is updated to match; the account-transfer fixture is unchanged.
- Fixed `bankc layout <project>` so it writes the JSON layout report as well as the markdown report.
- Fixed the command help text and CLI routing so the new commands are discoverable and executable.
- Fixed GitHub Actions CI so pnpm is installed before `actions/setup-node` tries to resolve `cache: "pnpm"`.
